How the pipeline moves.

A simple split: the Pi handles capture and rover-side telemetry; the laptop handles heavier inference, the dashboard, and local model workflows.

01

Capture (Pi & Camera)

Raspberry Pi gathers 1080p camera frames and IMU/GPS status telemetry directly at the edge.

Format: RAW MJPEG / 30fps
02

Transmit (WebSocket)

A low-latency WebSocket connection pipes raw streams and status strings continuously to the receiver.

Protocol: ws:// (TCP Port 8765)
03

Infer (YOLO & ONNX)

Windows receiver runs object identification models, overlays tracking boxes, and generates detections.

Latency: ~12ms (RTX TensorRT)
04

Act (Local LLM & Dashboard)

Dashboard records warnings, alerts operators, and pings Qwen/Ollama for automated text observations.

Reasoning: local qwen2.5-coder

Minimal Demo Setup

The simplest working rover needs only the Pi, a USB webcam, and the L911S motor driver.

USB Webcam Connect to Raspberry Pi USB port. Verify: ls /dev/video*
L911S Motors Pi GPIO5/6 (left) and GPIO13/19 (right) → L911S A-IA/A-IB and B-IA/B-IB
Motor Power Separate battery → L911S VCC/VM. Share GND with Pi.
Ultrasonic (optional) HC-SR04 TRIG→GPIO23, ECHO→GPIO24 via level shifter
Servo (optional) SG90 signal→GPIO18, powered from external 5V supply
Sensors (I2C)

MPU6050 IMU & HMC5883L Compass

Both share the I2C bus on GPIO2 (SDA) and GPIO3 (SCL). Connect VCC to 3.3V, GND to Pi GND.

MPU6050 I2C addr 0x68. Enable: "mpu6050_enabled": true
HMC5883L I2C addr 0x1E. Enable: "compass_enabled": true
Power Rules Never power motors from Pi 5V. Use separate battery. Share all GNDs.
ESP32-S3 Bridge (Optional)

Serial Motor Delegation

Pi USB → ESP32-S3 USB/UART. ESP32 GPIO4/5/6/7 → L911S. Baud 115200. Uses "M:left,right" protocol.

ESP32 GPIO4 L911S A-IA (left forward)
ESP32 GPIO5 L911S A-IB (left reverse)
ESP32 GPIO6 L911S B-IA (right forward)
ESP32 GPIO7 L911S B-IB (right reverse)
Firmware rover/esp32_s3/stasis_motor_controller.ino
Fault Tolerance

Graceful Degradation

Every sensor, motor output, and I2C device is optional. If a component is missing or fails, the system logs a warning and continues. Camera streaming and object detection run with zero hardware dependencies beyond the USB webcam.
