=======================================================================
  SECTION 1 — PROJECT OVERVIEW
=======================================================================

STASIS is a 4-wheeled autonomous rover that:
  - Accepts a GPS geofence boundary set via a web dashboard
  - Navigates autonomously within that boundary using obstacle
    avoidance, and stores learned paths in flash memory for
    efficient re-use on repeat visits
  - Detects humans using a two-stage computer vision pipeline
    (motion detection + ML person confirmation)
  - Reports detections in real time with GPS coordinates, snapshots,
    audible alerts, and visual alerts on the dashboard
  - Returns to a custom charging station automatically when
    battery is low or when scheduled
  - Is managed entirely via a lightweight web app hosted on the
    Raspberry Pi Zero W at the charging station, accessible from
    any browser on the local network

The system has three physical nodes:
  [A] ROVER UNIT         — ESP32-S3 + ESP32-CAM + sensors + motors
  [B] CHARGING STATION   — Raspberry Pi Zero W + ESP32-C3 Mini
  [C] DASHBOARD          — React web app served from the Pi,
                           accessed via any LAN browser

=======================================================================
  SECTION 2 — HARDWARE MANIFEST & PIN ROLES
=======================================================================

--- ROVER (Node A) ---

ESP32-S3 (Main Controller):
  - Controls all 4 motors via L298N or L293D motor driver
    Motor A (Left Front)  — IN1=GPIO4,  IN2=GPIO5,  ENA=GPIO6
    Motor B (Left Rear)   — IN3=GPIO7,  IN4=GPIO8,  ENB=GPIO9
    Motor C (Right Front) — IN1=GPIO10, IN2=GPIO11, ENA=GPIO12
    Motor D (Right Rear)  — IN3=GPIO13, IN4=GPIO14, ENB=GPIO15
  - Reads DS18B20 temperature sensor on GPIO16 (OneWire)
  - Reads MPU6050 (I2C): SDA=GPIO21, SCL=GPIO22
  - Reads NEO-6M GPS via UART2: RX2=GPIO17, TX2=GPIO18
  - Drives 16x2 or 20x4 I2C LCD (address 0x27) on same I2C bus
  - Communicates with ESP32-CAM via UART1: RX1=GPIO19, TX1=GPIO20
  - Communicates with ESP32-C3 Mini via ESP-NOW (primary),
    BLE (fallback)
  - Passive buzzer on GPIO2

ESP32-CAM (AI-Thinker module):
  - Connects to ESP32-S3 via UART (TX=U0TXD, RX=U0RXD, 115200 baud)
  - Runs two-stage detection pipeline:
      Stage 1: Frame differencing motion detection
               (pixel delta threshold > 3% of frame)
      Stage 2: If motion confirmed, run lightweight MobileNet-based
               person classifier (ESP-WHO or TFLite Micro)
               Confidence threshold: > 0.72 to fire alert
  - On confirmed detection:
      Capture 640x480 JPEG snapshot, base64 encode it, send JSON
      over UART to ESP32-S3:
      {"event":"human_detected","confidence":0.91,
       "timestamp":<ms>,"image":"<base64>"}
  - Streams MJPEG video over HTTP on port 81:
      GET /stream  → MJPEG feed
      GET /capture → single JPEG
      GET /status  → JSON health
  - Max stream framerate: 15fps
  - Detection cooldown: 30 seconds after each alert

--- CHARGING STATION (Node B) ---

Raspberry Pi Zero W:
  - ARM11, 512MB RAM — treat as resource-constrained Linux
  - Runs Python Flask + Flask-SocketIO backend (lightweight,
    appropriate for this hardware)
  - Serves built React dashboard as static files via Flask
  - Generates daily PDF patrol reports via fpdf2
  - Manages charging schedule and relay logic via RPi.GPIO
  - Communicates with ESP32-C3 Mini via hardware UART:
    Pi TX=GPIO14 (pin8), RX=GPIO15 (pin10), 9600 baud
  - Does NOT use WiFi directly — all network traffic is bridged
    through the ESP32-C3 Mini

ESP32-C3 Mini (WiFi & GPIO Bridge):
  - Creates WiFi Access Point: SSID="STASIS_NET", WPA2
    (or STA mode if existing network SSID defined in config.h)
  - Bridges all TCP/HTTP/WebSocket traffic between WiFi clients
    and Pi via UART (AsyncTCP-based TCP-UART bridge)
  - Receives ESP-NOW packets from ESP32-S3, forwards as JSON
    over UART to Pi
  - Receives JSON commands from Pi over UART, relays as ESP-NOW
    to ESP32-S3
  - GPIO15: charging relay control (HIGH = charging enabled)
  - GPIO16: emergency stop hardware signal to Pi (interrupt)
  - Watchdog: if no rover telemetry for 60s, send alert to Pi

Rover State Machine (enum + switch in main loop):
  STATE_IDLE        — waiting at charging station
  STATE_NAVIGATING  — moving toward geofence destination
  STATE_PATROLLING  — roaming within geofence boundary
  STATE_RETURNING   — heading back to charging station
  STATE_STUCK       — MPU6050 stuck/tilt detected, awaiting command
  STATE_CHARGING    — docked and charging
  STATE_EMERGENCY   — critical fault, full stop

Navigation & Path Memory (path_memory.h):
  - First visit to a GPS location: use reactive obstacle avoidance
    (MPU6050 terrain/bump detection + motor feedback)
  - Store successful path as GPS waypoint array in NVS flash:
    Key: "path_<geohash6>" → JSON [{lat,lon}, ...]
  - On revisit to same location (within 10m): load and follow
    the stored waypoint path directly
  - Invalidate and re-learn path if MPU6050 detects unexpected
    obstacle profile significantly different from stored

MPU6050 Behavior:
  - Poll at 20Hz
  - STUCK: linear accel < 0.05g for 3+ seconds while motors active
  - TILT: roll or pitch > 35 degrees
  - On either: stop motors, enter STATE_STUCK, broadcast ALERT packet
  - If no command after 5 minutes: attempt single auto-reverse,
    re-evaluate, then wait again
  - Alert type sent: STUCK or TILT accordingly

GPS Geofencing:
  - Store geofence as polygon (up to 10 GPS coordinate vertices)
  - Point-in-polygon ray casting check every 1 second
  - If outside boundary: navigate to nearest boundary point,
    then resume patrol

LCD Display (I2C, address 0x27, 16x2 or 20x4):
  Rotate every 3 seconds:
    Screen 1: "STASIS v2.0" + current state name
    Screen 2: GPS lat/lon (4 decimal places)
    Screen 3: "BAT:XX.XV  TMP:XX.XC"
    Screen 4: "SIG:OK/WEAK  CAM:ON/OFF"
    Screen 5: (on detection) "!! ALERT !!  HUMAN DETECTED"
              stays until alert acknowledged via dashboard
    Screen 6: (on stuck)    "!! STUCK !!  AWAITING CMD"

Buzzer (GPIO2, passive):
  - Human detected:  3 short beeps (100ms on / 100ms off) x3
  - Stuck/Tilt:      2 long beeps (500ms on / 200ms off) x2
  - Low battery:     1 slow beep every 10 seconds
  - Charging done:   ascending 3-tone melody (C4, E4, G4)

Coding rules for all firmware:
  - #pragma once in every header
  - No delay() in main loop — millis() timers only
  - Every module has init() and update() called from main loop
  - Serial debug output inside #ifdef DEBUG_MODE
  - All structs use __attribute__((packed))
  - NVS wrapped in nvs_flash_init error handling
  - esp_task_wdt watchdog enabled with 30s timeout

    uart_comms.h/.cpp        ← JSON over UART to ESP32-S3

Detection Pipeline:
  1. Capture at 320x240, convert to grayscale
  2. Frame delta vs previous frame → changed_pixels / total > 0.03
  3. On motion: run ESP-WHO person detection model
     (fallback: quantized INT8 MobileNetV2 96x96 via TFLite Micro)
  4. If person_confidence > 0.72: fire event
  5. Capture 640x480 JPEG, base64 encode, send JSON via UART
  6. 30 second detection cooldown

uart_handler.py:
  - Opens /dev/ttyS0 at 9600 baud via pyserial
  - Runs in daemon background thread (threading.Thread)
  - Reads newline-delimited JSON packets from ESP32-C3
  - Dispatches to telemetry_handler or alert_handler based
    on packet_type field
  - send_command(command_dict): serializes dict to JSON,
    writes to UART with newline terminator
  - Auto-reconnect on serial disconnect with 5s retry
  - All errors logged to /var/log/stasis/uart.log

telemetry_handler.py:
  - parse_telemetry(packet): validate fields, insert to DB
  - Emit Socket.IO event "telemetry" to all connected clients
  - Maintain in-memory rolling buffer of last 200 records
    for fast dashboard queries without DB hit
  - Trigger charging_controller check on each update

alert_handler.py:
  - parse_alert(packet): validate, insert to DB with image
  - Emit Socket.IO event "alert" to all connected clients
  - For HUMAN alerts: also log detection image to
    /var/stasis/snapshots/YYYY-MM-DD_HH-MM-SS.jpg
  - acknowledge_alert(alert_id, notes): update DB record

charging_controller.py:
  - Uses RPi.GPIO to control charging relay on CHARGING_RELAY_PIN
  - monitor(): called on each telemetry update
      If battery_voltage < BATTERY_LOW_THRESHOLD:
        send RETURN command via uart_handler
      If battery_voltage < BATTERY_CRITICAL_THRESHOLD:
        send EMERGENCY_STOP then RETURN
  - dock_detected(): if rover GPS within 2m of STATION_LAT/LON:
      activate relay (GPIO.output(CHARGING_RELAY_PIN, GPIO.HIGH))
  - undock(): deactivate relay
  - schedule_check(): runs every minute via schedule library
      If current time in charge window and rover not at station:
        send RETURN command

report_generator.py:
  - Uses fpdf2 to generate PDF daily reports
  - generate_report(date): queries DB for full day data and:
      - Header: STASIS logo text + date + summary line
      - Section 1: Patrol statistics
          Total distance (calculated from GPS lat/lon chain)
          Time in each rover state
          Battery charge cycles
      - Section 2: Human detections
          Count, table of detections with timestamp + GPS coords
          Embedded JPEG thumbnails (max 5 per page)
      - Section 3: Environmental data
          Temperature min/max/avg from DS18B20 log
      - Section 4: Incident log
          All stuck/tilt events with timestamps
      - Footer: generated timestamp + STASIS v2.0
  - Save to REPORTS_PATH/YYYY-MM-DD.pdf
  - Insert record into reports table
  - schedule_daily(): use schedule library to run at 23:55

REST API (all blueprints registered under /api/v1):

FIRMWARE (Arduino/C++):
  - #pragma once in all headers
  - All magic numbers in config.h as #define
  - No delay() — millis() timers only
  - init() and update() per module, called from main loop
  - #ifdef DEBUG_MODE wrapping all Serial debug prints
  - __attribute__((packed)) on all ESP-NOW structs
  - esp_task_wdt watchdog, 30s timeout
  - NVS operations with nvs_flash_init error handling

PYTHON BACKEND (Flask):
  - Python 3.11+ syntax
  - All config from .env via python-dotenv
  - Blueprints for all route groups
  - Background threads as daemon threads (threading.Thread,
    daemon=True)
  - All DB operations via parameterized queries (no f-string SQL)
  - try/except on all UART reads/writes with logging
  - RPi.GPIO cleanup in atexit handler
  - Logging to /var/log/stasis/ with rotating file handler
  - .env.example documents every required env variable

REACT DASHBOARD:
  - Functional components + hooks only
  - Zustand for global state
  - React Router v6
  - All API calls via custom hooks (no raw useEffect fetching)
  - Single useSocket hook manages Socket.IO lifecycle
  - Tailwind only — no inline styles, no CSS modules
  - All map ops via react-leaflet hooks
  - Mobile responsive (min 375px width)
  - PropTypes on all components
